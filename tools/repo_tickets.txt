Title: Text DFM lexer -- tokenize text form files
Issue: #4
Status: closed
Labels: enhancement
Body:
Implement a dedicated lexer for the DFM/FMX text form file format. This is
intentionally separate from delphi-lexer because DFM treats `{ hex }` as
binary data (not comments).

## Deliverables

- [ ] `source/Delphi.Forms.Token.pas` -- `TDfmTokenKind` enum and `TDfmToken` record
- [ ] `source/Delphi.Forms.Lexer.pas` -- `TDfmLexer.Tokenize()` producing `TDfmTokenList`
- [ ] `test/Test.Delphi.Forms.Lexer.pas` -- comprehensive lexer tests

## Token kinds

`dtkIdentifier`, `dtkInteger`, `dtkFloat`, `dtkString`, `dtkCharLiteral`,
`dtkEquals`, `dtkColon`, `dtkDot`, `dtkComma`, `dtkPlus`, `dtkMinus`,
`dtkLBracket`, `dtkRBracket`, `dtkLParen`, `dtkRParen`, `dtkLAngle`,
`dtkRAngle`, `dtkBinaryData`, `dtkWhitespace`, `dtkEOL`, `dtkEOF`

## Design invariants

- Round-trip: concatenating all Token.Text reproduces original source exactly
- Every character appears in exactly one token (no gaps, no overlaps)
- `{ hex }` produces `dtkBinaryData`, NOT a comment token
- Final token is always `dtkEOF`

## Acceptance criteria

- [ ] 0 warnings, 0 errors
- [ ] All lexer tests pass with zero memory leaks
- [ ] Round-trip verified on representative DFM snippets

Title: Text DFM parser -- recursive descent tokens to AST
Issue: #5
Status: closed
Labels: enhancement
Body:
Implement a recursive-descent parser that converts TDfmTokenList into a
TFormFile AST. Handles all DFM constructs: object/inherited/inline blocks,
properties with dotted names, and all value types (integers, floats, strings,
booleans, identifiers, sets, binary data, parenthesized lists, collections).

## Deliverables

- [ ] `source/Delphi.Forms.Parser.pas` -- `TDfmParser.Parse(Source): TFormFile`
- [ ] `test/Test.Delphi.Forms.Parser.pas` -- parser tests covering all value
  types, nested objects, inherited/inline forms, dotted property names,
  string concatenation with `+` and `#` char literals

## Grammar

```
FormFile       = Object EOF
Object         = ObjectKw Ident ':' Ident EOL PropertyOrChild* 'end'
ObjectKw       = 'object' | 'inherited' | 'inline'
Property       = DottedName '=' Value
Value          = NumericValue | StringValue | BoolValue | IdentValue
               | SetValue | BinaryValue | ListValue | CollectionValue
```

- [ ] All parser tests pass with zero memory leaks

Title: Binary DFM reader -- deserialize TPF0 format to AST
Issue: #7
Status: closed
Labels: enhancement
Body:
Implement a binary DFM reader that deserializes the TPF0 binary format into
the same TFormFile AST used by the text parser. Required for migrating
legacy Delphi systems that store forms in binary format.

## Deliverables

- [ ] `source/Delphi.Forms.BinaryReader.pas` -- `TDfmBinaryReader` with
  `ReadFromBytes`, `ReadFromStream`, `ReadFromFile` methods
- [ ] `test/Test.Delphi.Forms.BinaryReader.pas` -- binary reader tests using
  hand-crafted binary payloads

## Binary format

- Signature: `$FF` + `TPF0` (5 bytes)
- Object: ClassNameLen(1) + ClassName + NameLen(1) + Name
- Properties: NameLen(1) + Name + ValueType(1) + ValueData
- Zero-length name terminates property list
- Zero-length class name terminates children list
- Value type tags: vaList=1, vaInt8=2, vaInt16=3, vaInt32=4, vaExtended=5,
  vaString=6, vaIdent=7, vaFalse=8, vaTrue=9, vaBinary=10, vaSet=11,
  vaLString=12, vaNil=13, vaCollection=14, vaSingle=15, vaDouble=16,
  vaCurrency=17, vaDate=18, vaWString=19, vaInt64=20, vaUTF8String=21,
  vaUString=22

## Acceptance criteria

- [ ] 0 warnings, 0 errors
- [ ] All binary reader tests pass with zero memory leaks
- [ ] Reads binary DFM into correct AST structure
- [ ] Handles all value type tags

Title: Support typed collection items (item ClassName ... end)
Issue: #11
Labels: bug
Body:
The text parser only handles bare `item ... end` inside collection values.
DFM files can also have typed collection items: `item ClassName ... end`
(e.g. TToolButton, TListColumn with explicit class name). The parser
currently ignores the class name, which silently drops data and breaks
round-trip for forms using typed collections.

The binary reader has a similar gap -- collection items in binary format
can carry a class name that is not currently stored.

## Scope

- [ ] Update `TDfmParser.ParseCollectionValue` to detect and store the
  optional class name on collection items (store in `TFormObject.ClassName_`)
- [ ] Update `TDfmTextWriter.WriteCollectionValue` to emit the class name
  when present
- [ ] Update `TDfmBinaryReader` collection handling if class names appear
  in binary format
- [ ] Update `TDfmBinaryWriter` collection handling to write class names
- [ ] Add test cases for typed collection items in both text and binary paths
- [ ] Add a golden .dfm file with typed collection items

## Acceptance criteria

- [ ] `item TToolButton ... end` parses with ClassName_ = 'TToolButton'
- [ ] Round-trip passes for forms with typed collection items
- [ ] All existing tests still pass

Title: Preserve original binary value type tags for true binary round-trip
Issue: #12
Labels: enhancement
Body:
The binary writer always uses `vaDouble` for floats and `vaUTF8String` for
strings regardless of the original encoding. This means a binary
read->write cycle changes the byte representation when the original used
`vaExtended` (10-byte), `vaSingle`, `vaCurrency`, `vaDate`, `vaString`,
`vaLString`, `vaWString`, or `vaUString`.

Design invariant #2 ("binary round-trip: read -> AST -> write == original")
is not fully met for files using these value types.

## Approach

- [ ] Add an `OriginalValueType: Byte` field to `TFormValue` (0 = not set)
- [ ] `TDfmBinaryReader` stores the original value type tag when reading
- [ ] `TDfmBinaryWriter` uses `OriginalValueType` when set, falls back to
  current heuristic (smallest int, vaDouble, vaUTF8String) when not set
- [ ] For vaExtended: store the raw 10 bytes in a `TBytes` field so Win64
  can write them back without precision loss
- [ ] Add binary round-trip tests with vaExtended, vaSingle, vaCurrency,
  vaString, vaLString, vaWString, vaUString inputs

## Acceptance criteria

- [ ] Binary read -> write produces byte-identical output for all value types
- [ ] Programmatically constructed ASTs (no OriginalValueType) still work
- [ ] All existing tests still pass
